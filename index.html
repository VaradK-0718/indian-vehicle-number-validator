Vehicle Registration Number Validator

Deterministic Finite Automaton

A vehicle number is just a string a machine can read one character at a time.

This project builds a DFA that recognizes a simplified Indian vehicle registration format (e.g. MH12AB1234), STATE + RTO + SERIES + 1–4 digits, then walks that DFA through your input, state by state, so you can see exactly why it accepts or rejects.

This is a simplified academic model, and real Indian formats vary. Passing this syntactic check does not prove a registration is real or says anything about ownership.

The DFA

The states q7 to q10 are accepting (1 to 4 digits with value ≥ 1). The z states (q7z…q10z) mean “only zeros so far”, so 0 and 0000 are rejected. q3z blocks RTO 00. q1 stands for 18 states, one per first letter of a state code, so the state code is checked by the DFA itself. Every transition not drawn leads to the dead state qD, which never lets go. During simulation, the active state and the edge being followed are highlighted below.

Regular expression → DFA

A regular expression is a compact description of the same language this DFA recognizes. The two are formally equivalent — every regular language has some DFA, and every DFA describes some regular language — but the validator above never asks a regex to do the accepting or rejecting. Q
{q0, q1[A]…q1[W] (18), q2, q3, q3z, q4, q5, q6, q7…q10, q7z…q10z, qD}. Each state records how much of the pattern has been seen, plus whether the vehicle number is still all zeros.
Σ
The alphabet: {A–Z, 0–9} (spaces and hyphens are stripped before the DFA runs). Every input character must belong to this set, or the DFA treats it as invalid.
δ
The transition function, δ: Q × Σ → Q. Given a current state and one input character, it returns exactly one next state — see the transition table below.
q0
The initial state, before any character has been read.
F
The set of accepting states: {q7, q8, q9, q10}. A string is accepted only if the DFA ends in one of these: 1–4 final digits whose value is at least 1.

      About this project

      What is a DFA?

      A deterministic finite automaton is a machine with a finite number of states, a starting state, and a rule that says exactly one next state for every state/input-symbol pair. "Deterministic" means there is never a choice — the next state is always fully decided by the current state and the character being read.

      Why a DFA fits this problem

      A vehicle number in this simplified format is a fixed sequence of letter-or-digit positions. The DFA only needs to remember "which position am I at," which is exactly what a state can hold — no stack, no extra memory, no backtracking required.

      Acceptance condition

      After the final character is consumed, check the current state. If it is one of q7–q10, every character arrived in the right position and the string belongs to the language. Any other final state — including the dead state qD — means reject.

      Scope note

      Real Indian registration plates vary by state code, RTO code, and special series (BH-series, temporary plates, diplomatic plates, and so on). This project intentionally uses one simplified fixed format, STATE + RTO + SERIES + 1–4 digits, to keep the automaton small enough to inspect by eye. One real-world variant is included: an RTO written as a digit plus a letter (e.g. Delhi DL8CAF1).

      Project report

      Introduction

      Registration plates follow strict positional rules, which makes them a natural fit for regular languages. This project recognises a simplified Indian format with a DFA and shows every transition it makes.

      Problem statement

      Given a string over letters and digits, decide whether it has the form STATE CODE + RTO CODE + SERIES + VEHICLE NUMBER, using only a finite-state machine and no counters or backtracking.

      Objectives

      Define the language formally; build a DFA that recognises it; accept 1–4 digit vehicle numbers with value 1–9999; reject unknown state codes, RTO 00 and all-zero numbers; and display each step of the run.

      Alphabet

      Σ = {A–Z} ∪ {0–9}. Input is uppercased, and spaces and hyphens are removed. Any other character is rejected before the DFA runs.

      Language definition

      L = { s  |  s = S·R·E·N, S ∈ the 37 configured state/UT codes, R ∈ {01–99} ∪ {1–9 followed by a letter}, E ∈ [A–Z]², N ∈ [0–9]{1,4} with value 1 to 9999 }. L is finite, hence regular.

      Regular expression

      ^([A-Z]{2})([0-9]{2})([A-Z]{2})([0-9]{1,4})$ is the standard form. The implementation widens the RTO group to (0[1-9]|[1-9][0-9]|[1-9][A-Z]) to admit codes like 8C. State code and value are then checked independently, and the result must agree with the DFA.

      Algorithm

      1) Normalise the input. 2) Reject empty input or unsupported characters. 3) Start in q0 and apply δ to each character in turn. 4) Accept only if the final state is in F. 5) Cross-check with the regex and component rules, and explain any rejection from the state where qD was entered.

      Pseudocode

      s ← normalise(input)
if s is empty or has bad chars: REJECT
state ← q0
for each ch in s:
    state ← δ(state, ch)
    record (ch, state)
if state ∈ {q7,q8,q9,q10}: ACCEPT
else: REJECT

      Time complexity

      O(n) for an input of length n, with one table lookup per character. Valid inputs have at most 10 characters, so the work is effectively constant.

      Space complexity

      O(1) for the machine itself, since it keeps only the current state. The step-by-step trace uses O(n) extra memory for display.

      Applications

      Form validation, data cleaning of records, lexical analysis, and teaching examples for how DFAs, regular expressions and tokenisers relate.

      Advantages

      Deterministic, linear time, no backtracking, and every decision can be traced to one transition. The zero-tracking states let a finite machine enforce “value ≥ 1” without arithmetic.

      Limitations

      This is syntactic validation only: it cannot confirm that a registration exists, is current, or belongs to anyone. Real formats vary (BH-series, temporary, military and diplomatic plates), and the code list is a configuration, not an official registry.

      Conclusion

      A small DFA of about 40 states (18 of them first-letter states) recognises the language exactly. Variable-length numbers and the “not zero” rule fit in a finite-state machine, which supports the claim that plate syntax is a regular language.

      Possible extensions

      • Support additional real-world registration formats (BH-series, temporary plates)
      • Visualize the equivalent NFA before determinization
      • Walk through NFA → DFA subset construction
      • DFA minimization on this machine
      • Regular expression → NFA construction (Thompson's algorithm)
      • A custom DFA builder for other patterns
